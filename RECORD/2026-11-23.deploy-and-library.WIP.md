# Deploying this repository's templates, and templaitor as a library

Plan: [`ROADMAP/2026-11-23/deploy-and-library.md`](../ROADMAP/2026-11-23/deploy-and-library.md).

## 2026-11-23 · root project, createEngine, snapshot versions, project mode

- Request: "this repository will deploy the templates it includes; it must also be usable as a dependency of
  another project that uses it as its engine". Two questions were asked (deployment: send API of one
  project / multi-org with a preloaded org / only compiled output; package: engine + templates / engine
  only); no answer came, so the recommended options were implemented (stated in the reply).
- Root project: `templaitor.config.yml` + `templates/` (copy of the demo templates; `outDir: dist/templates`
  because `dist/editor` is the editor build). `make up` opens it by default (`PROJECT=examples/demo` for the
  demo). The accessibility test now covers both projects.
- `src/engine/message.js`: `renderMessage` (language by key/locale/language, pinned version, Jinja2 with the
  data, attachment names, snapshot for the attachments), `renderAttachments`, `renderPdfDocument`,
  `resolveLang`, `templateSource`. The send API (`sender.build`) uses it.
- `src/index.js` + `package.json` (`main`, `exports`: `.`, `./engine/*`, `./package.json`; `files` adds the
  root project and `.templaitor`): `createEngine({ cwd, overrides, fetch })` → `templates`, `components`,
  `layouts`, `render`, `attachments(msg)`, `pdf`, `compile` (Jinja2 output), `build`, `versions`, `version`;
  building blocks re-exported. `BUNDLED_PROJECT` = the package root.
- Versions without `.git`: `src/engine/snapshot.js` — `exportVersions` (every version of every template,
  component and layout, with its files) and a read-only `snapshotVersionStore`; `autoVersionStore` uses git,
  or the snapshot when there is no repository — and always the snapshot inside `node_modules`. CLI:
  `templaitor versions <template>` and `templaitor versions export [--out file]`. `.templaitor/` is
  git-ignored (also in the `.gitignore` written by "Create a git repository"). The store-level 200 cap moved
  to the façade so the export reads the whole history.
- Project mode (`project` / `TEMPLAITOR_PROJECT`, `apiKeys` / `TEMPLAITOR_API_KEYS` ≥ 24 chars,
  `admins` / `TEMPLAITOR_ADMINS`): forces fs storage and maps the folder to the org `project` (created at
  start; admins upserted as owners); editor writes → 403 (renders allowed); `POST /orgs` → 403; sign-up
  defaults to invite; env API keys compared in constant time; the org's SMTP falls back to the system SMTP;
  versions: git if the folder is a checkout, else the snapshot. `orgView` marks `readOnly`, and the editor's
  `canEdit` honours it ("Read-only" badge explains why).
- Deployment: Dockerfile copies `templaitor.config.yml`, `templates/` and `.templaitor/` (created empty in
  the build stage when no export ran); compose sets `TEMPLAITOR_PROJECT=/app` by default (empty → multi-org);
  Helm `project.enabled/dir/admins/apiKeys` (keys in the Secret); CI docker jobs check out the full history,
  export the versions before building, and smoke-test project mode (`/v1/templates`, `/v1/versions`);
  `make docker` exports first. npm `prepack` runs `scripts/export-versions.mjs` (skipped without git).
- Test harness: system emails now go through a stub transport (a configured system SMTP made the login of a
  project-mode test try to reach `smtp.deploy.test`).
- Checks: `node --test` 36/36 (new: library — bundled templates, Spanish email with the invoice PDF
  attachment, PDF, Jinja2 output, errors, own project; snapshot — export, no `.git`, read/resolve/read-only/
  dirty; project mode — env key, wrong key 401, render v1 vs current, `/v1/versions`, send with the
  deployment's SMTP, admin read-only editor, 403s, invitation-only sign-up). `npm pack` (343 files, 495 kB)
  installed in a separate project: `createEngine()` lists and renders the bundled templates.
