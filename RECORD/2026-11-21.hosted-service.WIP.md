# Hosted service

Plan: `ROADMAP/2026-11-21/hosted-service.md`.

## 2026-11-21 · request and decisions

Request: deploy templaitor on a server as a service, with user login, organizations and a sending service
for hosted emails and for HTML sent by the client. Follow-up: **local mode must keep working**.

Decisions taken with the user:
- Template storage: **configurable** (`fs` folder per org, optionally mapped to an existing folder; or `db`).
- Database: **SQLite now, Postgres later** (data-access layer in `src/service/repo.js`, portable SQL).
- Login: **email OTP + passkeys** (no passwords).
- Sending: **SMTP per organization** with a persistent queue.

## 2026-11-21 · first implementation (phases Foundation, Authentication, Editor, Sending, Deployment)

- `templaitor serve` (Node ≥ 22.13, built-in `node:sqlite`); configuration from `templaitor.server.yml` or
  `TEMPLAITOR_*` variables (`src/service/config.js`). The local CLI/editor is untouched and still runs on
  Node ≥ 20 (the service is imported only by `serve`); the editor detects the mode via `/auth/session`.
- Database: migrations (users, sessions, otp_codes, passkeys, challenges, orgs, memberships, invitations,
  api_keys, messages, files). Tokens, codes and API keys stored as HMAC-SHA256; org SMTP passwords
  AES-256-GCM with `TEMPLAITOR_SECRET`.
- Auth: OTP (6 digits, 10 min, 5 attempts, 5 codes / 15 min per email, per-IP limits, no account
  enumeration), passkeys with `@simplewebauthn/server` 14 (discoverable credentials), 30-day sliding
  sessions, CSRF check on the `Origin` of cookie-authenticated writes. `signup: open | invite`.
- Organizations: roles viewer/editor/admin/owner, invitations accepted on sign-in, last-owner protection.
- Editor per org: `/api/*` and `/static/*` are routed to the active org's project handler (the same
  `createHandler` as the local editor); viewers can only read and render; with the `db` driver every write
  is synced back to the database. Test sends use the org's SMTP.
- Sending: `POST /v1/send` (hosted template + data in a language, or raw HTML with base64/URL attachments),
  `POST /v1/render`, `GET /v1/messages/:id`, `GET /v1/templates`; Idempotency-Key; per-org rate limit;
  queue worker with backoff 30 s → 6 h (6 attempts), 5xx SMTP answers are permanent; attachments of hosted
  templates are rendered by the worker from a snapshot of the template taken at enqueue time.
- Security decisions: PDF **sandbox** in service mode (WeasyPrint through its Python API with a URL
  fetcher that only allows `data:` and the static directory — supports the WeasyPrint ≥ 67 `URLFetcher`
  class and the older function API —; Chromium blocks every request outside the static route; Prince is
  refused because it cannot be restricted). Remote attachments use an SSRF-safe fetch (address check inside
  the socket `lookup`, redirects re-checked). Verified: a template with `file:///etc/hostname`,
  `/etc/passwd` and `169.254.169.254` renders without any of them.
- Editor UI: sign-in screen (code + passkey), first-organization screen (blank or demo project), org
  switcher, read-only badge for viewers, settings dialog (organization, members/invitations/roles, SMTP,
  API keys with a curl example, send log with the rendered email, account with passkeys).
- Deployment: multi-stage `Dockerfile` (WeasyPrint in a venv, non-root, `/data` volume, health check),
  `deploy/docker-compose.yml` + `deploy/.env.example`, `templaitor.server.example.yml`, `make serve`,
  `make docker`.
- Checks: `npm test` 28/28 (5 new service tests: OTP login, orgs/roles/CSRF, send API hosted + raw +
  idempotency + retries, db storage driver, SSRF/encryption). End to end in Chromium: local editor still
  loads without login; service sign-in with an email code, demo org creation, SMTP + API key from the UI,
  passkey added with a virtual authenticator, sign-out and sign-in with the passkey, `POST /v1/send` →
  delivered to a local SMTP server with `factura-2026-0042.pdf` attached, visible in the send log.
- Not verified: the Docker image build (no Docker daemon in this environment).

## 2026-11-21 · Postgres adapter, multi-instance safety and send-log retention

- The data-access layer is **async** now (repo, SQLite adapter and every caller). The SQLite adapter keeps
  transactions safe on its single connection with an AsyncLocalStorage-based lock (queries outside the
  transaction wait for it).
- **Postgres adapter** (`src/service/db/postgres.js`, `pg` 8): `?` → `$n`, transactions on a dedicated
  client found through AsyncLocalStorage, BIGINT returned as numbers. Migrations are dialect-aware
  (`BIGINT`/`BYTEA` vs `INTEGER`/`BLOB`) and serialized with an advisory lock. The queue is claimed with
  `UPDATE … WHERE id = (SELECT … FOR UPDATE SKIP LOCKED) RETURNING *`.
  Selected with `database.driver: postgres` + `database.url` or `TEMPLAITOR_DATABASE_URL`.
- Decision: **SQLite is single-instance**. Two instances on one SQLite file deadlock (node:sqlite is
  synchronous: a blocked `BEGIN IMMEDIATE` stalls the event loop of the instance holding the lock). Several
  instances → Postgres (documented; the multi-instance test runs on Postgres only).
- **db storage across instances**: each instance keeps a stamp (file count + latest `updated_at`) of what it
  materialized and re-materializes (write aside + swap) when another instance changed the files. Bug found
  and fixed: the editor response was sent before the sync to the database finished, so another instance
  (or the next request) could read the previous version; the sync now runs before the response ends. The
  org (SMTP) is re-read on every editor request.
- **Retention**: `send.retentionDays` (default 30, `TEMPLAITOR_RETENTION_DAYS`, 0 = keep): the hourly
  maintenance replaces the payload (HTML, text, attachments) of finished messages with `{"purged":true}`;
  metadata stays (`purged: true` in the API/log).
- PDF sandbox: the Python used is now the interpreter of the `weasyprint` executable (shebang) unless
  `TEMPLAITOR_PYTHON` is set — with `pipx install weasyprint` (CI) the system python3 cannot import it.
- Deployment: `deploy/docker-compose.postgres.yml` (Postgres 16 with health check) validated with
  `docker compose config`; `deploy/.env` is git-ignored now (it holds secrets — it was not ignored before).
- CI: Postgres 16 service + `TEMPLAITOR_TEST_POSTGRES_URL`; actionlint OK.
- Checks: `npm test` 29/29 (SQLite) and 34/34 with a local Postgres 16 (service suite on both: OTP, orgs/
  roles, send API, two instances draining one queue without double sends, retention, db storage across two
  live instances). End to end in Chromium against `serve` on Postgres + db storage: sign-in with code and
  passkey, demo org, SMTP/API key from the UI, `/v1/send` delivered with the invoice PDF; local editor
  unchanged.
