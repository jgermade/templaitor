# SVG icons and shareable preview URL

## 2026-11-23 · every icon is an SVG

Request: "instead of characters or the system checkbox, always SVG" (screenshot of the subject bar: ♿ ✓,
✓, the native `text` checkbox; top bar flags and ➤).

- `editor/src/components/Icon.svelte`: one set of inline SVG icons (24×24, `currentColor`), decorative by
  default (`aria-hidden`) or with `label` (`role="img"`). Replaces every character/emoji used as an icon in
  the editor: ✓ ✕ ⚠ ♿ ◆ ⧉ 📎 ✎ ⚙ ➤ ← → ↑ ↓ ↔ ↗ ↻ ↶ ↷ ⤓ ⇥ ▸ ▾ ● 🖥 📱 🗑 🌐 🔗 🔑 🖼 ＋ and the `+` prefixes of
  buttons. The MJML block catalog (`src/shared/components.js`) now holds icon names instead of characters.
- Icon-only buttons got an `aria-label` (they only had `title`).
- `components/Checkbox.svelte` (checkbox and radio): the native input is kept (keyboard, screen readers)
  but invisible; an SVG box shows the state, with a focus ring. Used for `text`, "Same demo data", boolean
  parameter defaults, SMTP TLS and the starter radios of the service.
- Flags: `components/Flag.svelte` + `lib/flags.js` with `country-flag-icons` (MIT, dev dependency): each
  country is a separate SVG file loaded on demand (`import.meta.glob`, keyed by file name — the alias keys
  did not match at first: every flag fell back to the language code). Catalan, Basque and Galician flags
  are inline SVGs. Without a region: the language code. In `<select>` options (no images possible) the flag
  is shown next to the select instead. `dist/editor` grows by ~1 MB (267 small files, only fetched when used).
- Canvas (iframe) chips: the ⚙ 🔗 🌐 `::before` emoji are CSS masks with SVG data URIs; the "Missing
  translation" placeholder has an SVG background icon. Plain-text places that cannot hold an SVG (toasts,
  dialog buttons, `title`) lost the symbol instead ("Send", "attachments: …").
- Convention added to AGENTS.md.
- Checks: build without new warnings; Chromium screenshots of the design view (top bar, subject bar,
  sidebar, outline, inspector, canvas chips), preview with the accessibility report, compare view; axe-core
  on the top bar: 0 violations (one contrast failure of the language-code fallback disappeared once flags
  loaded). Pre-existing axe findings in the CodeMirror data editor are unchanged.

## 2026-11-23 · shareable preview URL

Request: open the preview at a "compatible" URL (the button opened `about:blank` and wrote the HTML into it:
not reloadable or shareable).

- `GET /preview/<id>?lang=<key|locale>&kind=…&version=…` in the editor server (`previewPage`): the saved
  files (or a version, through `resolveVersion`) rendered with the demo data, `<base href="/">` so static
  images load, `<title>` = rendered subject (+ ` · v3`), `Cache-Control: no-store`; errors as a small HTML
  page (404 unknown document/language/version). Routed in the hosted service through the org's editor
  (members only, viewers included) and in the Vite dev server.
- Editor: the button opens that URL; with unsaved changes it asks "Save and open" first (decision: the URL
  shows saved files, so what is shared is what is stored). The Versions dialog has a preview link per
  version.
- Checks: engine test (languages by key/locale/default, 404s, layout, `version=v1` after the files changed);
  service test (viewer 200, signed out 401); in Chromium the button opens
  `/preview/orders/order-confirmation?lang=es`, the title survives a reload and both static images load.
  `node --test` 33/33.
