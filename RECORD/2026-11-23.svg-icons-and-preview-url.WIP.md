✓, the native `text` checkbox; top bar flags and ➤).

- `editor/src/components/Icon.svelte`: one set of inline SVG icons (24×24, `currentColor`), decorative by
  default (`aria-hidden`) or with `label` (`role="img"`). Replaces every character/emoji used as an icon in

  translation" placeholder has an SVG background icon. Plain-text places that cannot hold an SVG (toasts,

## 2026-11-23 · shareable preview URL

Request: open the preview at a "compatible" URL (the button opened `about:blank` and wrote the HTML into it:
not reloadable or shareable).

- `GET /preview/<id>?lang=<key|locale>&kind=…&version=…` in the editor server (`previewPage`): the saved
  files (or a version, through `resolveVersion`) rendered with the demo data, `<base href="/">` so static
  images load, `<title>` = rendered subject (+ ` · v3`), `Cache-Control: no-store`; errors as a small HTML
  page (404 unknown document/language/version). Routed in the hosted service through the org's editor
  (members only, viewers included) and in the Vite dev server.
- Editor: the button opens that URL; with unsaved changes it asks "Save and open" first (decision: the URL
  shows saved files, so what is shared is what is stored). The Versions dialog has a preview link per
  version.
- Checks: engine test (languages by key/locale/default, 404s, layout, `version=v1` after the files changed);
  service test (viewer 200, signed out 401); in Chromium the button opens
  `/preview/orders/order-confirmation?lang=es`, the title survives a reload and both static images load.
  `node --test` 33/33.

## 2026-11-23 · layouts are email or PDF layouts

- Request: "layouts should be email layouts or PDF layouts" (the Layout select of an email offered
  document.layout.mjml).
- A layout declares `format: email | pdf` in a frontmatter (new: layouts had none). `readLayoutFile` /
  `layoutFormat` (resolver) strip it wherever a layout is read (applyLayout, wrapFragment for component
  previews, layoutNeeds); `listLayouts` reports `format` (null when undeclared → offered to both, so existing
  projects keep working). The component preview layout prefers a non-PDF layout. Compile warns when the
  template's format and its layout's differ. `createLayout(project, id, { format })` writes the frontmatter
  (PDF layouts start with a white body). Demo and repository layouts declare their format.
- Editor: `store.layoutsFor(format)`; Template settings and New template list only the layouts of the format
  (a mismatching current layout stays listed as "(not a PDF layout)"); switching Format switches to the first
  layout of the new format (with a notice); a layout's settings have a Format button choice; "New layout"
  asks for the name and what it is for — `promptDialog` gained an optional `choice` (returns
  `{ value, choice }`); the template picker shows the layouts' format icon.
- Checks: engine test (formats listed, frontmatter absent from the output, mismatch warning, createLayout,
  undeclared = null); Chromium — email template offered only base.layout, switching to PDF moved it to
  document.layout with a notice, New template lists by format, New layout "statement" for PDF documents
  written with `format: pdf`, the layout's Format choice; axe on the New layout dialog: 0 violations.
  `node --test` 39/39.
