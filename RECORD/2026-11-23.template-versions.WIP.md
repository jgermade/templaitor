# Template versions

Request: a version system for templates, also in local mode with git.
Plan: [`ROADMAP/2026-11-23/template-versions.md`](../ROADMAP/2026-11-23/template-versions.md).

## 2026-11-23 · version stores (git and database), editor API and Versions dialog

- A version is a snapshot of **one document** (template, component or layout: `.mjml`/`.yml`/`.json5`; a
  layout only its `.mjml`) with a description, author, date and a per-document number (v1, v2…).
- `src/engine/versions.js`: façade (`listVersions`, `readVersion`, `saveVersion`, `initVersions`) over a
  pluggable `project.versionStore` (`info · list · read · save · init?`).
- `src/engine/history.js` is now the **git store**: `list` = `git log -- <files>` + `rev-list --count` for
  the numbers + `status --porcelain` for "saved but not versioned"; `read` = `git show rev:./path`; `save` =
  `git add -A -- <files>`, `git diff --cached --quiet` (nothing new → 409) and `git commit -m … -- <files>`,
  so other changes the user has staged are not committed; `init` = `git init` + `.gitignore` (`/<outDir>/`,
  `node_modules/`) + commit "Initial version" of the whole project. git runs from the project folder with
  paths relative to it (works with symlinked folders; the previous code mixed the realpath from
  `--show-toplevel` with non-resolved paths). Identity: the repository's; when there is none,
  `-c user.name/user.email` with `templaitor <templaitor@localhost>`. `--author` sanitized (`<>`, newlines).
- Hosted service: `fs` storage → git store; a non-mapped org folder must be its **own** repository
  (`rootMustBe`, so a data directory inside some checkout never commits to that checkout); `scaffold` runs
  `git init` for new orgs (errors are logged, versions stay off). Author = signed-in user
  (`req.templaitorActor`, set by the service; the local server never sets it). `db` storage → database
  store (`src/service/versions.js`, migration 2: `versions` table, files as JSON + SHA-256 to detect "no
  changes"/dirty, numbers in a transaction with UNIQUE(org, kind, doc, number) and one retry).
  Dockerfile: `git` installed in the runtime image.
- Editor API: `GET /api/versions`, `GET /api/version`, `POST /api/versions`, `POST /api/versions/init`
  (`/api/history` removed). Viewers can list/read (GET); saving needs the editor role (existing rule).
- Editor: **Versions** button in the top bar → `<dialog>` (VersionsPanel): where versions are stored (git
  branch / database), "Describe this version" + **Save version** (saves the draft first if dirty; disabled
  when nothing changed), status line (unsaved draft / saved but not versioned / up to date), list with
  number, description, author, relative date (absolute in `title`), short hash, "current"; **Compare**
  (opens the compare view with the version as A) and **Restore** (into the draft through `store.update`,
  so Undo reverts it; confirmation when the draft has unsaved changes). Without a repository: **Create a git
  repository**. The compare view lists versions of any storage (`ver:<rev>`).
- Decision: restore never writes files; the user reviews and saves (and can save a version "Restore v3").
- Checks: `node --test` 32/32 (new engine test: no repo → init with no git identity anywhere → v1 by
  "templaitor", 409 with no changes, save commits only the document while another file stays staged,
  author sanitized, read by full/short rev, layouts, a terminal commit counted as v3, invalid revisions;
  new service test: fs org → git with author = user, viewer 403 on save, init 409; db org → v1/v2 rows,
  default message, dirty, read by id, invalid id 400, init 400). In Chromium on a copy of the demo without
  git: create repository → v1, edit subject → Save version → v2 (only the template's `.yml` in the commit),
  Restore v1 → draft dirty with the old subject, Ctrl+Z → back, Compare v1 → compare view with v1 as base.
  axe-core 4.10 on the dialog (no repository, list, 390 px): 0 violations; no horizontal overflow at 390 px.
  Fixed during the check: the dialog showed "Versions are not available" while the first list was loading.
