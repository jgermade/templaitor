# Email attachments

## 2026-11-21 · attachments: local PDF templates per language and remote files

Request: emails have a list of attachments, local or remote; local ones are rendered in the email's
language.

- Frontmatter `attachments:` (emails only). Entry forms: `{ template, filename?, context? }`,
  `{ url, filename? }`, or the short forms `- group/name` / `- https://…`. Normalized in
  `src/shared/attachments.js` (browser-safe, shared with the editor).
- `src/engine/attachments.js`:
  - `resolveAttachments` (compile time): `$` commands resolved in `url`/`filename` with the email
    context (`$lang`, `$t`, `$link`), Jinja2 kept. Local entries are resolved to the attached template
    compiled in the email's locale; if the document lacks that language it falls back to its first
    language with a warning. Warnings for missing templates, non-PDF templates and invalid entries.
  - `renderAttachment`: local → PDF with the configured engine; remote → `fetch` (15 s timeout, 20 MB
    max, clear errors).
- Decision: data of a local attachment = the email's data (backend sends the same context), or the email
  variable named by `context` (e.g. `context: invoice`). In previews the document's own demo data fills
  the gaps. Reason: the email and the document usually have different variable shapes, and the backend
  only has the email's context at send time.
- Decision: default file name `<template-name>.pdf` / last URL segment; localized names through
  `filename: "$t('key')"` in the email's `.yml` (demo: `factura-{{ invoice.number }}.pdf` /
  `invoice-{{ invoice.number }}.pdf`).
- Compile writes `<name>.<locale>.attachments.json` for the backend (local entries: `template`, `locale`,
  `html`, `options` → compiled files relative to `outDir`; remote: `url`; both: `filename`).
- Server: `POST /api/attachment` (one attachment rendered with demo data), `POST /api/send` attaches
  them all (nodemailer); `listTemplates` now reports `format` (email/pdf).
- Editor: "Attachments" group in Template settings (add local PDF / remote file, template select, context,
  file name, remove; frontmatter rewritten through the YAML document), 📎 chips in the subject bar that
  open each attachment rendered with the demo data in the current language.
- Demo: `orders/order-confirmation` attaches `documents/invoice` with `context: invoice`.
- Checks: `npm test` 23/23 (4 new tests, including a real WeasyPrint render of the attached invoice);
  editor build OK; in the browser: chips per language (`factura-2026-0042.pdf` ↔ `invoice-2026-0042.pdf`),
  adding a remote file from the UI, `/api/attachment` returns the English/Spanish PDF; a test send to a
  local SMTP server delivered the email with the PDF attached (33 KB, `application/pdf`).

Pending / ideas:
- Remote attachments are not checked for accessibility (PDF/UA); could validate them with veraPDF when
  they are PDFs.
- Conditional attachments (e.g. only when a variable is set) are not supported yet.
