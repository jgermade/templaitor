# Editor mountable under a sub-path

## 2026-11-26 · relative URLs in the editor client

- Request (from doomus): serve the local editor behind another dev server at `/templaitor/`
  (doomus' Vite proxies `/templaitor/` → `templaitor editor` on `:3333`, stripping the prefix).
  The client used root-absolute URLs (`/api/...`, `/static/`, `/preview/`, `/auth/session`),
  so under a prefix they hit the host app instead (e.g. doomus' own `/api/`).
- Changes:
  - `editor/src/lib/api.js`: every editor API call is relative (`api/project`, …).
  - `editor/src/lib/host.js`: `previewUrl` resolves `preview/<id>` against `location.href`;
    `staticUrl` returns `static/<path>`. The `__TEMPLAITOR_HOST__` overrides are unchanged.
  - `editor/src/lib/service.svelte.js`: the hosted-mode probe is `auth/session` (relative). The
    other `/auth/*` and `/orgs/*` calls stay absolute: they only run in the hosted service,
    which is served at the root.
  - `editor/index.html`: favicon `./favicon.svg`.
  - `src/server/server.js` (`previewPage`): `<base href>` is relative to the request path
    (`/preview/a/b` → `../../`), so `/static/…` in a preview resolves against the editor root
    wherever it is mounted. Tests updated (`engine.test.js`, `service.test.js`).
- Safe at the root too: client routing is hash-only, so the page path is always the mount
  point. The mount must end with `/` (the host redirects `/templaitor` → `/templaitor/`).
- Checked with Playwright behind doomus' Vite proxy: every request stays under
  `/templaitor/`, none hits the root `/api/`, the doomus templates load and render, and
  `/templaitor/preview/customers/login-code` has `<base href="../../">` →
  `document.baseURI` `http://localhost:5173/templaitor/`.
- Tests: 46 pass, 0 fail. In this container `engine.test.js` and `service.test.js` never exit
  after their tests finish (a Chromium instance stays open): the same happens without this
  change, so it is environmental here (CI is green).
