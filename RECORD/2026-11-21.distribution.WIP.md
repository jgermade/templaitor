# Distribution: binary, Docker, Helm and one-line setup

## 2026-11-21 · binary bundles, Helm chart, GHCR publishing and setup.sh

Request: make the build deployable as a binary, with Docker and with Helm; one-line setup at
`jgermade.github.io/templaitor/setup.sh` offering install, update, reinstall and uninstall.
Plan: [`ROADMAP/2026-11-21/distribution.md`](../ROADMAP/2026-11-21/distribution.md).

- `templaitor version` / `--version` / `-v` (used by the installer to check the bundle runs).
- `scripts/build-binary.mjs`: per-target archive with the app, production deps (`npm ci --omit=dev
  --ignore-scripts`), `dist/editor`, the demo project and the official Node.js (downloaded from nodejs.org,
  checked against `SHASUMS256.txt`; `--node` reuses a local binary). Fails if a native module appears.
  Launcher resolves symlinks so `<prefix>/bin/templaitor → <prefix>/lib/templaitor/bin/templaitor` works.
  `make binary` builds the local target.
- Decision: archive + bundled Node instead of a Node SEA single file (reasons in the roadmap).
- `deploy/helm/templaitor`: Deployment (Recreate, non-root uid 1000, seccomp, probes on `/healthz`),
  Service, optional Ingress, PVC and Secret kept on uninstall, generated `TEMPLAITOR_SECRET` reused on
  upgrades, ConfigMap with the `TEMPLAITOR_*` settings, `helm test` pod; validation for replicas > 1.
- Dockerfile: OCI labels (`image.source` links the GHCR package to the repo).
- `site/setup.sh` (published by `build-site.mjs`, which copies `site/`): binary (default), docker and helm
  methods; `status`; `--version`, `--prefix`, `--port`, `--namespace`, `--values`, `--purge`, `-y`.
  Update only downloads when the latest tag differs (redirect of `/releases/latest`, no API) and compares
  `VERSION` inside the archive as a fallback; SHA-256 verified; a new binary that does not run is rolled
  back to the previous one. Docker: `~/.config/templaitor/docker.env` with a generated secret, volume
  `templaitor-data`, port kept across updates. Helm: `upgrade --reuse-values`; purge deletes PVC + Secret.
- CI: `build.yml` builds the 4 bundles, smoke-tests linux-x64 (`version`, `compile --strict`, `serve` +
  `/healthz`), lints/renders/packages the chart (`templaitor-chart-<v>.tgz`, since `npm pack` already
  writes `templaitor-<v>.tgz`), and a `docker` job builds the image and checks `/healthz` + a WeasyPrint
  PDF. `release.yml` pushes the multi-arch image and the OCI chart to GHCR.
- Landing: install one-liner in "Get started". Also fixed the screenshots on mobile: the global `img`
  rule lacked `height: auto`, so images kept their `height` attribute (860 px) while shrinking to the
  viewport width (stretched). The PDF page preview is capped at 240 px on phones.
- Checks: `test/setup-script.test.js` (install → already installed → update no-op → update 1.0.0 → 1.1.0
  → pinned reinstall → bad checksum rejected and old version kept → uninstall needs `--yes` → removed).
  Real bundle built here with the local Node: `version`, `compile` of the demo and `serve` + `/healthz`
  from the extracted archive; setup.sh binary flow through `cat setup.sh | sh` against a file:// mirror;
  docker/helm flows against stub commands (call sequence checked). `sh -n` and `dash -n` OK.
- Not verified here: no Docker daemon and no `helm` binary in this environment (downloading helm was not
  allowed), so the image build and `helm lint/template` run only in CI.

## 2026-11-22 · release v0.1.3: Helm push failed

- Release v0.1.3 succeeded except the `helm` job: `helm push` → `Error: failed to perform "Tag" on
  destination: sha256:…: not found`. Cause: `azure/setup-helm` defaults to the latest Helm, now 4.3.2,
  whose push fails against ghcr.io at the tagging step (login and upload were fine).
- Fix: Helm pinned to v3.19.0 (build.yml and the new `chart.yml`). Publishing moved to `chart.yml`
  (manual or called by release.yml) that takes `templaitor-chart-<version>.tgz` from the GitHub release,
  so a release's chart can be republished without a new version. v0.1.3: run `chart` with `0.1.3`.
- Not verified here (no helm, no GHCR credentials): the next `chart` run is the check.
