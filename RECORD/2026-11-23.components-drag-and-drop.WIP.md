# Components are added by dragging

## 2026-11-23 · drag from the Components panel to the canvas or the structure

- Request: "components should only be added by dragging them" (screenshot of the Components panel, where a
  click inserted the component next to the selection; dragging was not possible at all).
- Panel rows are draggable (`role="button"`, grip icon, `cursor: grab`); a click does nothing. Keyboard
  alternative kept on purpose (accessibility is a hard requirement, WCAG 2.1.1 / 2.5.7): Enter or Space on
  a focused component inserts it after the selection.
- Drag state moved to the store (`store.drag = { id, tag, comp }`), shared by the panel, the Structure tree
  (dropping a component inserts an `$import` before/after/inside, validated with `accepts`) and the canvas.
- Canvas: the editor computes the valid targets of the component's root tag (`store.dropTargets`: elements
  and component instances, with before/after/inside) and sends them to the iframe; the bridge finds the
  closest valid node under the pointer, draws a line (or a dashed box for "inside") labelled
  "<component> · after", and posts the drop back. The canvas keeps the dragged component itself because the
  panel's `dragend` can arrive before the iframe's `drop` message.
- Bug found while testing: the first block under the pointer was a component instance (an `$import` text
  node), which was not a target; instances are targets now (before/after).
- Checks: in Chromium — a click inserts nothing; a mouse drag to the tree inserts the component; Enter
  inserts it; on the canvas (synthetic drag events inside the iframe: Playwright's mouse drag does not
  reach a cross-origin iframe) the line appears after the banner and the drop inserts the component.
  `node --test` 36/36. Not verified: a real mouse drag into the canvas iframe.

## 2026-11-23 · right panel always visible: inspector or the "Add" library

- Request: "this aside can always be shown; when nothing is selected, put the available blocks and
  components there" (screenshot of the inspector of a component instance).
- Design view: the right column is always there — the inspector of the selection, or `views/LibraryPanel.svelte`
  ("Add": Blocks grid + Components list) when nothing is selected (Esc or the first breadcrumb go back).
  Blocks and Components left the left sidebar (Messages, Structure and settings stay there).
- Blocks are draggable too (a click still adds the block at the end and selects it). The drag state is
  generic now: `store.drag.item` = `blockItem(tag)` / `componentItem(comp)` with the tags it may take;
  `fitIn(item, pid)` picks the block itself or a column/section wrapper; `dropTargets(item)` and
  `dropItem(item, targetId, where)` serve the canvas and the tree (replacing dropComponent).
- Found while testing: after a drop the new block is selected, the library (the drag source) unmounts and
  its `dragend` never fires; the tree drop now clears the drag state itself (the canvas already did).
- Checks: Chromium — library shown with nothing selected; click on "Text" adds and selects it (inspector);
  Esc brings the library back; dragging "Text" onto the canvas (synthetic events in the iframe) shows
  "Text · after" and inserts it; axe on the library: 0 violations. `node --test` 36/36.
