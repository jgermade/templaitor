# Display logic of a block (Jinja2 if / for)

## 2026-11-23 · "Show only if" and "Repeat for each" in the block's properties

- Question: how to add other Jinja2 elements such as `if` and loops. Answer: inline in texts/tables, or a pair
  of "HTML / Jinja" blocks around blocks (fragile: two loose nodes); a Condition / Repeat container block was
  proposed. The user preferred putting it in the block's properties — implemented that way.
- `src/shared/logic.js` (browser-safe): `markerOf` (an `<mj-raw>` holding exactly `{% if x %}`,
  `{% for a in b %}`, `{% endif %}` or `{% endfor %}`), `unitOf` (the matching markers right around a block,
  outer → inner), `logicMap` (logic per block id + the marker ids that belong to a block), `setLogic`
  (rewrites the markers, `if` outside `for`; strips `{% %}` / `{{ }}` from the input; validates the loop
  variable), `moveUnit` / `removeUnit` / `duplicateUnit` / `unitsOf`.
- Decision: keep the storage as `<mj-raw>` markers (what the demo already used for `tracking_url`), not a new
  syntax: compiled MJML/Jinja2 is unchanged and existing templates gain the UI for free. Unpaired markers are
  left as plain HTML / Jinja blocks (visible, so a broken pair is noticed).
- Editor: `store.logic` (derived), `logicOf`, `setLogic`; move up/down, drag and drop, duplicate and delete
  work on the whole unit; inserting after a selection lands after its unit (never between a block and its
  `{% endif %}`); drop targets before/after a block use the unit's bounds. Structure tree hides the markers
  and shows badges ("tracking_url", "item in items"). Inspector: "Display" section for any block whose parent
  accepts `<mj-raw>` — Show only if (datalist of demo variables), Repeat for each (item + list, datalist of
  the demo data's arrays); changes apply on change (blur / Enter) and the selection follows the block.
  Icons `branch` and `repeat`.
- Found while testing: the design canvas renders with nunjucks too, so a block whose condition is false in
  the demo data vanished from the canvas (could not be selected). Design mode now replaces the markers by
  labels ("if vip", "for each item in items") that are not Jinja2; inside a column the label is a table row
  (a `<div>` between rows was moved above the table by the browser). Preview applies the logic; the raw
  output keeps the Jinja2.
- Checks: engine tests (markers, units, if + for order, move/duplicate/remove with markers, clearing,
  invalid loop variable, delimiter stripping; design/preview/raw behaviour) — `node --test` 38/38. Chromium:
  demo's cta-button shows "tracking_url" in the tree and in Display; setting `vip` + `item in items` on a
  text writes the four markers in the right order (Code view) and labels it on the canvas; axe on the
  Display section: 0 violations.

Pending / ideas:
- `{% else %}` / `{% elif %}` branches and "show if the list is empty" (`{% for %}…{% else %}`).
- A preview toggle to see the hidden branch without editing the demo data.
