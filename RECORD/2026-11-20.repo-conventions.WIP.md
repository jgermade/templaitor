## 2026-11-20 · fix: PDF view re-rendering in a loop

- Symptom: the PDF view showed "Rendering PDF…" every ~5 s without any edit.
- Cause: the render `$effect` read `url` (to choose the debounce delay), so every new PDF changed `url`
  and re-triggered the effect (0.9 s debounce + render time ≈ 5 s). The cleanup effect also depended on
  `url` and could revoke the freshly created object URL.
- Fix (`editor/src/views/PdfView.svelte`): read `url` untracked, re-render only when the draft key
  (texts, language, engine) changes, revoke the previous object URL after swapping, and revoke the last
  one in `onDestroy`.
- Verified in the browser: 1 render in 20 s idle, exactly one render per edit or engine change.
