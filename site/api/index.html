API reference

Every HTTP endpoint of templaitor. JSON in, JSON out (UTF-8), unless an endpoint says otherwise. Try the editor API without installing anything in the demo: it runs the same engine in your browser.

Surfaces and authentication

Send API · /v1

Hosted service. Render and send a template for one recipient from your backend. Authorization: Bearer tpl_… (an organization's API key, or a deployment key in project mode).

Editor API · /api

What the visual editor calls. Locally (templaitor editor) it is open on 127.0.0.1; in the hosted service it needs the session cookie and acts on the active organization.

Account · /auth, /orgs

Hosted service only: sign-in with an emailed code or a passkey, organizations, members, SMTP, API keys and the send log. Session cookie.

Hosted service rules. Cookie-authenticated writes must come from the service's own origin (Origin header), or they are rejected with 403. Roles, from least to most: viewer (read and render only: GET, plus POST /api/preview, /api/pdf, /api/pdf/validate and /api/attachment), editor (edits templates), admin (members, SMTP, API keys) and owner. In project mode the templates come from the deployed repository: editor writes answer 403.

Errors

Errors answer with an HTTP status and { "error": "message" }. A data contract violation (422) adds details: [{ path, message, template }].

StatusMeaning
400Invalid request: missing field, invalid YAML/JSON5, unknown language or version.
401Missing or invalid API key, or not signed in.
403The role or the deployment does not allow it, or a cross-site write.
404Template, version, message or route not found.
409Conflict: already exists, no changes since the last version, choose an organization first…
413Body too large (2 MB for the account and editor APIs, 40 MB for /v1; images 5 MB).
422data does not fulfil the template's data contract, or Jinja2 failed with it.
429Too many sign-in attempts.
501Not available here: no PDF engine installed, veraPDF missing.
502The SMTP server could not be reached.

Send API

Base URL: your hosted service, e.g. https://templaitor.example.com. Every request carries Authorization: Bearer tpl_…. The organization comes from the key.

Messages

POST /v1/send API key

Queues an email. Either a hosted template rendered with your data in the recipient's language (with its attachments, PDFs included), or raw HTML you rendered yourself. Delivery uses the organization's SMTP and retries with backoff.

FieldDescription
to, cc, bccAddress, comma-separated string or array ("Ada <ada@example.com>" works). Up to 50 recipients in all.
templateHosted: template id, e.g. orders/order-confirmation.
langHosted: language key (es), locale (es-ES) or a locale's language (es-MX → es). Default: the template's first language.
dataHosted: object with the template's variables. Checked against its data contract (422 when it does not match).
versionHosted, optional: 3, "v3", "latest" or a revision. Sends the template as it was at that version; without it, the current files.
subject, html, textRaw: the message. text defaults to a conversion of html.
attachmentsRaw: [{ filename, content (base64) | url, contentType? }], 20 MB each.
replyToOptional reply-to address.
fromOptional sender; must use the organization's domain.

Header Idempotency-Key (optional): a retry with the same key returns the original message (200) instead of sending twice. Answers 202 with the message (see GET /v1/messages/:id) and warnings when there are any.

curl https://templaitor.example.com/v1/send \
  -H "Authorization: Bearer tpl_…" -H "Content-Type: application/json" \
  -H "Idempotency-Key: order-1042" \
  -d '{ "template": "orders/order-confirmation", "lang": "es", "to": "ada@example.com",
        "version": "latest", "data": { "first_name": "Ada", "order_id": "1042" } }'

HTTP/1.1 202 Accepted
{ "id": "6f1c…", "status": "queued", "kind": "hosted", "template": "orders/order-confirmation",
  "version": { "number": 3, "rev": "…", "short": "v3" }, "locale": "es-ES",
  "subject": "Acme | Pedido 1042 confirmado", "to": ["ada@example.com"], "cc": [], "bcc": [],
  "attempts": 0, "attachments": ["factura-1042.pdf"], "createdAt": 1764000000000, … }

POST /v1/render API key

Same body as /v1/send; renders without sending (recipients are optional).

{ "subject": "…", "html": "<!doctype html>…", "text": "…", "locale": "es-ES",
  "version": null, "attachments": ["factura-1042.pdf"], "warnings": [] }

GET /v1/messages/:id API key

Delivery status of a message: queued · sending · sent · failed.

{ "id": "6f1c…", "status": "sent", "kind": "hosted", "template": "orders/order-confirmation",
  "version": null, "locale": "es-ES", "subject": "…", "to": ["ada@example.com"], "cc": [], "bcc": [],
  "attempts": 1, "attachments": [], "lastError": null, "smtpMessageId": "<…>", "purged": false,
  "createdAt": 1764000000000, "sentAt": 1764000001200, "nextAttemptAt": null }

Templates

GET /v1/templates API key

The organization's templates.

[{ "id": "orders/order-confirmation", "format": "email", "langs": ["es", "en"] },
 { "id": "documents/invoice", "format": "pdf", "langs": ["es", "en"] }]

GET /v1/schema?template=&version= API key

The template's data contract (data: in its frontmatter) as JSON Schema: what data must fulfil. version is optional. 404 when the template declares no contract.

GET /v1/versions?template=&limit= API key

Versions of a template, newest first, to pick one for /v1/send { version }.

{ "available": true,
  "versions": [{ "number": 3, "rev": "…", "short": "v3", "message": "New footer", "author": "Ada", "date": "2026-11-23T10:00:00.000Z" }] }

Editor API

The API of the visual editor: local (templaitor editor, make up) or hosted (session cookie, active organization). Documents are identified by id and kind: template (default), component or layout (a layout's id is its file name, e.g. base.layout.mjml). A draft is the unsaved source of a document: { mjml, yml, data, lang?, kind? }, where yml holds the subject and messages per language and data the demo data (JSON5).

Project

GET /api/project

Project settings the editor needs.

{ "name": "Demo", "locales": { "es": "es-ES", "en": "en-US", … }, "defaultLocale": "es",
  "templatesDir": "templates", "outDir": "dist", "layouts": ["base.layout.mjml", "document.layout.mjml"],
  "files": ["_layouts/base.layout.mjml", "_shared/links.yml"], "links": { "homepage": "https://example.com" },
  "smtp": { "label": "mailpit", "web": "/mailpit/" }, "componentsDir": "_components", "assetsUrl": "{{ assets_url }}",
  "pdf": { "engines": [{ "id": "weasyprint", "label": "WeasyPrint", "pdfua": true, "available": true, … }],
           "defaultEngine": "weasyprint", "configured": "auto", "verapdf": "veraPDF (docker)" } }

Templates, components and layouts

GET /api/templates

[{ "id": "customers/email-verification", "name": "email-verification", "group": "customers",
   "format": "email", "langs": ["es", "en"], "kind": "template" }]

POST /api/templates

Creates a template: { id, layout?, langs?, format? } (format: email or pdf). It inherits the variables and messages its layout needs. Returns the new document (as GET /api/template).

GET /api/template?id=&kind=

A document's source files. A layout also brings the template it is previewed with (previewFrom) and its texts and data.

{ "kind": "template", "id": "customers/email-verification", "name": "email-verification",
  "mjml": "---\nlayout: base.layout.mjml\n…", "yml": "subject:\n  es: …", "data": "{\n  first_name: \"María\", … }" }

PUT /api/template

Saves a document: { id, kind?, mjml, yml, data }. yml and data are validated (400 on invalid YAML or JSON5). For a layout only mjml is saved. Returns the saved document.

DELETE /api/template?id=&kind=

Deletes a template, component or layout → { "ok": true }.

GET /api/components

Reusable components with their parameters and where they are used.

[{ "id": "banner", "kind": "component", "format": "email", "langs": ["es", "en"],
   "importPath": "_components/banner", "rootTag": "mj-section",
   "params": { "image": { "type": "image", "label": "Image", "default": "{{ assets_url }}/banner-order.svg" }, … },
   "usedBy": [{ "kind": "template", "id": "orders/order-confirmation" }] }]

POST /api/components

Creates a component, optionally from a selection: { id, mjml?, yml?, data? } (the messages of yml and the JSON5 data become the component's own). Returns the new document.

GET /api/layouts

[{ "kind": "layout", "id": "base.layout.mjml", "name": "base.layout", "format": "email",
   "usedBy": [{ "kind": "template", "id": "customers/email-verification" }] }]

POST /api/layouts

Creates a layout: { id, format } (email or pdf). 409 if it exists.

Rendering

POST /api/preview

Compiles a draft and renders it with its demo data. mode: preview (default), design (annotated for the visual canvas) or raw (Jinja2 left unrendered).

{ "locale": "es-ES", "langKey": "es", "subject": "Acme | Valida tu email", "format": "email",
  "html": "<!doctype html>…", "text": "VALIDA TU DIRECCIÓN DE EMAIL…", "meta": { "layout": "base.layout.mjml", … },
  "pdf": null, "attachments": [], "warnings": [], "errors": [],
  "a11y": [], "a11yReport": { "standard": "WCAG 2.1 AA · EN 301 549", "issues": [], "checks": [{ "id": "lang", "wcag": "3.1.1", "status": "pass", … }] },
  "hasContract": true, "contract": { … }, "usedVars": ["first_name", …] }

POST /api/compile

Writes the Jinja2 output (HTML, text, subject per locale) to outDir: { id? , samplePdf? } (one template or all; samplePdf also renders a sample PDF of PDF templates).

{ "files": ["dist/customers/email-verification.es-ES.html", …], "issues": [] }

POST /api/pdf

The PDF of a draft with its demo data: draft + engine? (weasyprint · prince · chromium · auto) + name?. Answers application/pdf with the headers X-Templaitor-Engine (engine used) and X-Templaitor-Warnings (URL-encoded JSON array). 501 when no engine is installed.

POST /api/pdf/validate

Renders the draft's PDF and validates it against PDF/UA-1 with veraPDF.

{ "engine": "weasyprint", "locale": "es-ES",
  "validation": { "validator": "veraPDF 1.28", "profile": "PDF/UA-1 validation profile", "compliant": true,
                  "passedRules": 106, "failedRules": 0, "failedChecks": 0, "rules": [] } }

POST /api/attachment

One attachment of a draft (draft + index, default 0) rendered with the demo data: a local PDF template or a downloaded remote file. Answers the file itself, with its Content-Type and file name.

POST /api/send

Sends a test of the draft (with its attachments) to to through the project's SMTP (smtp in templaitor.config.yml, e.g. Mailpit).

{ "ok": true, "messageId": "<…@localhost>", "attachments": ["factura-2026-0042.pdf"] }

Versions

Named snapshots of a document: git commits locally, database rows in the hosted db storage.

GET /api/versions?id=&kind=&limit=

Versions of a document, newest first (limit: 50 by default, 200 at most). dirty: the saved files differ from the latest version. canInit: versions can be turned on (POST /api/versions/init).

{ "backend": "git", "available": true, "canInit": false, "branch": "main", "dirty": false,
  "versions": [{ "id": "a1b2c3…", "rev": "a1b2c3…", "short": "a1b2c3d", "number": 2, "message": "New footer",
                 "author": "Ada", "date": "2026-11-23T10:00:00+01:00" }] }

GET /api/version?id=&kind=&rev=

A document at a version: the version's fields plus its mjml, yml and data.

POST /api/versions

Saves the document as it is on disk as a new version: { id, kind?, message? }. In the hosted service the signed-in user is the author. 409 when nothing changed since the last version.

POST /api/versions/init

Turns versions on for a project that has none (git: git init and a first commit).

Files and images

GET /api/file?path=

An auxiliary project file (layouts, partials, _shared/links.yml), path relative to the templates root.

{ "path": "_shared/links.yml", "content": "# URLs shared by every template…" }

PUT /api/file

Writes an auxiliary file: { path, content } (YAML is validated) → { "ok": true }.

GET /api/assets

Images of the static folder (served at /static/).

[{ "path": "logo.svg", "size": 194 }, { "path": "banner-order.svg", "size": 505 }]

POST /api/assets?name=

Uploads an image: the body is the file itself (binary, 5 MB at most). A free name is picked when name is taken.

curl -X POST "http://127.0.0.1:3333/api/assets?name=hero.png" --data-binary @hero.png

{ "path": "hero.png", "size": 48213 }

Pages

GET /preview/:id?lang=&kind=&version=

A shareable HTML page: the saved document (or a version: v3, a revision…) rendered with its demo data. lang accepts a key or a locale.

GET /static/:path

Files of the project's static folder (static in templaitor.config.yml, _shared by default).

Hosted service

Account endpoints of templaitor serve (Docker image, Helm chart). They use the session cookie set by sign-in.

Sign-in and account

GET /auth/session

The current session. Signed out: { mode: "service", user: null, signup, appName }. (The local editor has no such route: that is how the editor tells both apart.)

{ "mode": "service", "appName": "templaitor",
  "user": { "id": "…", "email": "ada@example.com", "name": "Ada", "passkeys": 1 },
  "orgs": [{ "id": "…", "slug": "acme", "name": "Acme", "role": "owner", "storage": "fs", "mapped": false }],
  "activeOrg": { "id": "…", "slug": "acme", … } }

POST /auth/code

Emails a one-time sign-in code: { email } → { "ok": true } (the same answer whether the address can sign in or not). Rate-limited (429).

POST /auth/code/verify

Signs in with the code: { email, code }. Sets the session cookie. 403 when sign-up is by invitation and the address was not invited.

POST /auth/logout

Ends the session and clears the cookie.

POST /auth/passkeys/login/options

WebAuthn authentication options (a challenge) to sign in with a passkey.

POST /auth/passkeys/login

Verifies the browser's WebAuthn assertion and signs in.

GET /auth/passkeys

The signed-in user's passkeys.

POST /auth/passkeys/register/options

WebAuthn registration options to add a passkey.

POST /auth/passkeys/register

Verifies the browser's WebAuthn attestation and stores the passkey.

PATCH /auth/passkeys/:id

Renames a passkey: { name } (60 characters at most).

DELETE /auth/passkeys/:id

Removes a passkey.

PATCH /auth/me

Updates the profile: { name } (80 characters at most).

Organizations

An organization view is { id, slug, name, role, storage, mapped, project?, readOnly? }.

GET /orgs

The organizations of the signed-in user.

POST /orgs

Creates an organization and makes it active: { name, slug?, starter? } (starter: demo for the example templates, blank otherwise). 403 in project mode.

GET /orgs/:id

An organization; admins also get its smtp settings.

PATCH /orgs/:id admin

Renames it: { name }.

DELETE /orgs/:id owner

Deletes the organization and its templates: { confirm: "<slug>" }.

POST /orgs/:id/activate

Makes it the session's active organization (the one the editor API acts on).

Members and invitations

GET /orgs/:id/members

{ members, invitations } (pending invitations only for admins).

POST /orgs/:id/invitations admin

Invites someone by email: { email, role? } (editor by default; only an owner grants owner). Sends the invitation email.

DELETE /orgs/:id/invitations/:iid admin

Cancels an invitation.

PATCH /orgs/:id/members/:uid admin

Changes a member's role: { role }. The organization always keeps at least one owner.

DELETE /orgs/:id/members/:uid

Removes a member (admin), or leaves the organization (yourself).

SMTP

GET /orgs/:id/smtp admin

The organization's SMTP. The password is never returned.

{ "host": "smtp.example.com", "port": 587, "secure": false, "user": "apikey", "from": "Acme <no-reply@acme.com>", "hasPassword": true }

PUT /orgs/:id/smtp admin

Sets it: { host, port?, secure?, user?, password?, from? }. Omit password to keep the stored one (it is stored encrypted); an empty host removes the SMTP.

POST /orgs/:id/smtp/test admin

Queues a test email to to (default: you). Returns the message, as in the send log.

API keys

GET /orgs/:id/keys admin

The organization's API keys (name, prefix, creation and last use; never the key).

POST /orgs/:id/keys admin

Creates a key: { name? }. The answer carries key (tpl_…): it is shown only once.

DELETE /orgs/:id/keys/:kid admin

Revokes a key.

Send log

GET /orgs/:id/messages?limit=&before=&status=

Messages sent by the organization, newest first (before: a createdAt for paging; status: queued · sending · sent · failed).

GET /orgs/:id/messages/:mid

One message with its html and text (until the retention period purges them).

Health check

GET /healthz

Liveness probe → { "ok": true }.
